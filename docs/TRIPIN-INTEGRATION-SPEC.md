# 旅點 TRIPIN — 整合開發規格與驗收基準

> 此檔案是開發規格，不代表下列功能已完成。僅於 feature/tripin-global-smart-shopping 分支開發，禁止直接覆寫 main。

## 品牌與導覽
- 名稱：旅點 TRIPIN；標語：每一站，都不錯過。
- 定位：國內外旅行管理為主，購物提醒為特色。
- 首頁呈現**所有旅行封面卡片**，不僅是進行中旅行。
- 導覽：首頁、旅行、購物、地圖、我的。原收藏庫、照片、行程、錢包、旅行資訊與回饋入口不可刪除。
- 視覺：鼠尾草綠、奶油白、柔和蜜桃色；手機、平板、桌機響應式。

## 購物與智慧找店
- 新增商品時**不自動搜尋**；由使用者按「幫我找店家」觸發。
- 全球目的地與商品通用；支援當地語言查詢、手動輸入店家及精確座標。
- 搜尋結果須附資料來源，明確區分「可能販售」與「已確認庫存」。
- 庫存狀態：官方顯示有貨／官方顯示缺貨／庫存未知；顯示查詢時間。不得捏造即時庫存。
- 店家候選結果由使用者選擇是否加入 GPS 提醒；不得全部自動訂閱。
- 地圖、AI、零售商 API 經由安全後端代理；設定配額、快取與成本上限；不得在前端暴露私密金鑰。

## GPS 提醒
- 保留目前網站前景定位功能，100/200/500/1000m 等設定、同店合併未購商品、已購排除、冷卻及離開重入。
- 網頁背景/鎖屏不承諾可靠提醒；原生 iOS/Android 背景 geofencing 另行開發與實機驗證。
- 拒絕定位、離線、定位漂移、店家同名不同分店、跨時區等情境要有降級處理。

## 資料與安全
- 保留 V34 既有資料結構並提供版本化遷移與回復機制；不得清空 localStorage。
- 多人雲端同步需真實身份驗證、資料列權限隔離、後端授權與備份；不能以純 GitHub Pages/localStorage 宣稱多人安全。
- 保護既有 Google Apps Script 回饋流程；測試中攔截請求，不寄送測試回饋。
- XSS、輸入驗證、金鑰外洩、權限繞過、速率限制及壓力測試列入驗收。

## 完整驗收
1. 原有旅行 CRUD、封面、照片、行程、收藏、錢包、回饋全部回歸測試。
2. 新增商品後不觸發搜尋；按「幫我找店家」才查詢；搜尋失敗可手動設定。
3. 多國語言與不同城市測試；無庫存來源必須顯示未知。
4. GPS 同店合併、已購排除、重複通知抑制、權限拒絕測試。
5. 手機／桌面版 UI、鍵盤操作與無障礙檢查。
6. 多使用者資料隔離、負載、安全及資料遷移測試；留下可重現的測試報告。
7. 所有檢查通過後提供可測試預覽網址，正式版 main 仍需使用者確認才合併。

## 已知現況
- main 存在單頁 index.html、Playwright 測試與 GPS/安全稽核文件。
- 此規格尚未構成全球找店 API、庫存 API、雲端會員系統或原生 App 的實作。
